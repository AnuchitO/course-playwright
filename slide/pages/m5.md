# 3. Step 1 and 2: Page Object, then fixture

```ts {1-3|5-9|11-14|all}
export class BookingPage {
  constructor(private readonly page: Page) {}
  readonly continueButton = this.page.getByRole('button', { name: /continue to payment/i });

  async fill(p: Passenger) {
    await this.page.getByPlaceholder('e.g. John').fill(p.firstName);
    await this.page.getByPlaceholder('e.g. Doe').fill(p.lastName);
    // ... email, phone
  }
}
// fixtures.ts
export const test = base.extend<{ bookingPage: BookingPage }>({
  bookingPage: async ({ page }, use) => use(new BookingPage(page)),
});
```

<div class="small">Light version: <b>locators + one method per user intent</b>. No assertions inside, no giant base classes.</div>

<!--
SAY: A Page Object is just a class that owns the locators of one screen. Keep it light: when the placeholder changes, you edit one file. A fixture then hands the object to tests that ask for it, with `bookingPage` in the test arguments; Playwright builds it per test.
Keep assertions in the test: the test reads as the spec, the page object as the plumbing.
DEMO: open solutions/lab-5/pages/BookingPage.ts and fixtures.ts side by side.
Q: "Why not a base class with every helper?" It becomes a junk drawer; compose small objects instead.
TIME: 4 min.
NEXT: The test now reads like intent.
-->

# Step 3: log in once, reuse everywhere (`storageState`)

```ts {1-4|5-9|all}
// auth.setup.ts: runs ONCE
setup('create a returning traveller', async ({ page, request }) => {
  const token = randomUUID();                       // Qoomlee identity = UUID in localStorage
  await createBookingViaApi(request, token, flight); // data via API, zero clicks
  await page.goto('/flights');
  await page.evaluate((t) => localStorage.setItem('qoomlee:session:token', t), token);
  await page.context().storageState({ path: '.auth/traveller.json' });
});
// playwright.config.ts
projects: [ { name: 'setup', testMatch: /auth\.setup\.ts/ },
  { name: 'chromium', dependencies: ['setup'], use: { storageState: '.auth/traveller.json' } } ]
```

<div class="small">Qoomlee has no login screen: a traveller is an anonymous id in the browser. Same idea as logging in.</div>

<!--
SAY: Every test that needs "a traveller who already has a booking" used to click through a whole booking. Now a setup project does it once through the API, saves the browser state to a file, and every test starts with that identity loaded.
Honest note: the app has no login; here the identity is a UUID in localStorage which the backend uses to track a traveller's bookings. If your app has real auth, same pattern: log in via UI or API in setup, save storageState.
DEMO: show .auth/traveller.json, then the returning-traveller test (3 lines, no clicks before the assertion).
Q: "Is the state shared between tests?" The file is read-only input; each test gets its own browser context that starts from it.
TIME: 4 min.
NEXT: Run it.
-->
