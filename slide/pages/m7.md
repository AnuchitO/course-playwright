# 3. One config: projects, parallel, retries

```ts {1-4|5-8|9-12|all}
export default defineConfig({
  fullyParallel: true,
  forbidOnly: !!process.env.CI,                       // no stray test.only
  retries: process.env.CI ? 2 : 0,                    // retries only in CI
  workers: process.env.CI ? 2 : undefined,
  use: { trace: 'retain-on-failure', screenshot: 'only-on-failure', video: 'retain-on-failure' },
  projects: [
    { name: 'chromium',      use: { ...devices['Desktop Chrome'] } },
    { name: 'firefox',       use: { ...devices['Desktop Firefox'] } },
    { name: 'webkit',        use: { ...devices['Desktop Safari'] } },
    { name: 'mobile-chrome', use: { ...devices['Pixel 5'] } },
  ],
});
```

<!--
SAY: Projects run the same tests on different browsers and devices: Safari is WebKit, the phone is a Pixel 5 viewport and user agent. `fullyParallel` and workers cut wall time. Retries only in CI, and remember: a test that passes on retry is reported flaky: a bug with a label, not a green tick.
Instructor note: this exact config (plus the setup project) is solutions/lab-7/playwright.config.ts and was run against Chromium, Firefox, WebKit and mobile Chrome.
Q: "Do I need all 4 browsers on every commit?" No, see the next slide.

# GitLab CI: keep the evidence

```yaml {1-4|5-8|9-14|all}
e2e-smoke:
  image: mcr.microsoft.com/playwright:v1.60.0-noble   # browsers + OS deps; match your version
  script:
    - npm ci
    - npx playwright test --grep @smoke --project=chromium
  artifacts:
    when: always                 # even (especially) when it fails
    expire_in: 7 days
    paths:
      - playwright-report/
      - test-results/            # traces, screenshots, videos
    reports:
      junit: results/junit.xml
```

<div class="small">Placeholder: <code>BASE_URL</code> points at your staging. Full file: <code>solutions/lab-7/.gitlab-ci.yml</code>.</div>

<!--
SAY: The container image already has the browsers and system libraries: do not apt-get them yourself. `artifacts: when: always` is the line people forget: without it a failed job uploads nothing and you are back to "no idea why". Download test-results, run `show-trace`, done.
The image tag must match your @playwright/test version.

4. Read `solutions/lab-7/.gitlab-ci.yml`. Where is the evidence saved?

::criteria::
- [ ] `--grep @smoke` runs on all 4 projects
- [ ] You can say what `retries: 2` hides
- [ ] You can point at the artifact lines

::hint::
Tag the title: `test('... @smoke', ...)`. A pass-on-retry shows as **flaky** in the report.

::recap::
- **Projects** = browsers and devices; **workers** = speed; **retries** = flaky flag, not a fix
- **`@smoke`** every push, full suite nightly
- CI must **upload traces and the report**, even on failure
