# What a good E2E test looks like

- [ ] Named as a **behavior** a user cares about
- [ ] **Independent**: runs alone, in any order, in parallel
- [ ] **Unique data** per run; test-mode payments only
- [ ] **No sleeps**, user-facing locators, web-first assertions
- [ ] One **journey**, not one 80-line script
- [ ] **Evidence on failure**: trace, screenshot, report

# What NOT to E2E test

<div class="grid grid-cols-2 gap-6">
<div>

```txt
        /\   E2E      few, slow, high value
       /  \  UI (mocked backend)
      /____\ Contract
     /______\ Integration / component
    /________\ Unit        many, fast, cheap
```

</div>
<div>

- Every validation rule combination: **unit**
- Price and tax math: **unit**
- Does service A match service B: **contract**
- Everything that needs a button click to *reach*: think twice

**Keep E2E for the 3 to 5 journeys that must never break.**

</div>
</div>

# Cheat sheet

<div class="grid grid-cols-3 gap-4 text-sm">
<div>

**Locators**
`getByRole('button', {name})`
`getByLabel` · `getByPlaceholder`
`getByText` · `getByTestId`
`.first()` `.filter({hasText})`

</div>
<div>

**Assertions** (retry)
`toBeVisible` `toHaveText`
`toHaveURL` `toHaveValue`
`toHaveCount` `not.…`
`{ exact: true }` `{ timeout }`

</div>
<div>

**CLI**
`test` · `--ui` · `--debug` · `--headed`
`--grep @smoke` · `--project=x`
`--trace on` · `show-trace` · `show-report`
`codegen <url>`

</div>
</div>

**Never:** `waitForTimeout` · `expect(await x.isVisible())` · CSS/XPath chains · real card numbers
