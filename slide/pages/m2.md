# 3. The simple solution: wait for the thing, not the clock

<div class="grid grid-cols-2 gap-5">
<div class="label-bad">Fixed sleep + one-shot check</div>
<div class="label-good">Web-first assertion</div>

```ts {all}
await page.goto(resultsUrl);

await page.waitForTimeout(500);

const visible = await page
  .getByText('QM101').first()
  .isVisible();
expect(visible).toBe(true);
```

```ts {all}
await page.goto(resultsUrl);

await expect(
  page.getByText('QM101').first()
).toBeVisible();
```
</div>

<div class="small mt-3">The assertion <b>retries</b> until it is true or 5 s pass. The one-shot <code>isVisible()</code> checks once, right now.</div>

<!--
SAY: Same intent, two lines versus six. Left: wait half a second and look once. If the API takes 600 ms, it fails. Right: ask Playwright to keep looking until QM101 is visible. It is faster on a fast machine and patient on a slow one.
The trap: `expect(await locator.isVisible())` looks like an assertion, but the await turns it into a snapshot. Web-first means the matcher gets the locator, not the value.
DEMO: the Lab 2 starter file is this left column. Show it red with SLOW_API=3000, then fix it.
Q: "What if the page really takes 20 s?" Pass `{ timeout: 20_000 }` to that one assertion. Do not add sleeps.

# Auto-wait: what Playwright checks before every action

- **Attached** to the page
- **Visible**
- **Stable** (not animating)
- **Enabled**
- **Receives events** (nothing covers it)

<div class="small mt-4">Then it clicks. If not all true in time: a clear timeout error that names the locator.</div>

```ts {all}
await page.getByRole('button', { name: /select/i }).first().click(); // waits for you
```

<!--
SAY: Actions wait on their own. That is why most of your sleeps can simply be deleted. For assertions, use the web-first matchers: toBeVisible, toHaveText, toHaveURL, toHaveCount, they all retry.
Show: a click on the results page when the flight list is still loading just works; the Select button does not exist yet, so the action waits for it.
Q: "Does fill wait too?" Yes, same actionability checks (editable instead of enabled).

Fix `starter/tests/lab2-flaky.spec.ts` for slow machines.

1. Run it with `SLOW_API=3000`: it fails
2. Delete the sleep, use a web-first assertion
3. Pass with **and** without the delay
4. Add: click **Select**, expect the booking form

::criteria::
- [ ] No `waitForTimeout`
- [ ] No `isVisible()` inside `expect`
- [ ] Green at `SLOW_API=0` and `3000`

::hint::
`await expect(locator).toBeVisible()` retries. `expect(await locator.isVisible())` does not.

::recap::
- Never `waitForTimeout`: wait for **a condition**
- Actions auto-wait; assertions are **web-first** and retry
- A retry that passes is not green, it is **flaky**: fix the cause
