# 3. One test per behavior

```ts {1-4|6-9|11-17|all}
test.beforeEach(async ({ page, request }) => {
  const day = await firstDepartureDate(request);          // a real date from the API
  await page.goto(`/flights/results?origin=BKK&destination=SIN&departure=${day}&passengers=1&cabin=economy`);
  await page.getByRole('button', { name: /select/i }).first().click();
});

test('empty form shows a required error on every field', async ({ page }) => {
  await page.getByRole('button', { name: /continue to payment/i }).click();
  await expect(page.getByText('Required', { exact: true })).toHaveCount(3);
});

test('email without @ is rejected', async ({ page }) => {
  await page.getByPlaceholder('e.g. John').fill('Jane');
  await page.getByPlaceholder('john.doe@example.com').fill('not-an-email');
  await page.getByRole('button', { name: /continue to payment/i }).click();
  await expect(page.getByText('Valid email required')).toBeVisible();
});
```

<!--
SAY: Common setup goes in beforeEach, then each test is one behavior with a name that states it. When "email without @ is rejected" goes red, you know the rule, not just "booking broke".
Point at `{ exact: true }`: getByText matches substrings, case-insensitive, so 'Required' also matches 'Valid email required' (4 elements, not 3). Real surprise, real fix.
DEMO: remove `exact` live, show the count mismatch error, put it back.
Q: "Where do dropdowns and date pickers come in?" selectOption for <select>; the calendar is buttons, we already used it in Module 1.

# The journey: once, tagged `@smoke`

```ts {1|2-6|7-12|13-14|all}
test('full journey: book, pay with test card, get a PNR @smoke', async ({ page }) => {
  await page.getByPlaceholder('e.g. John').fill('Jane');
  await page.getByPlaceholder('e.g. Doe').fill('Doe');
  await page.getByPlaceholder('john.doe@example.com').fill(PASSENGER.email());   // unique each run
  await page.getByPlaceholder('000 000 000').fill('0800000000');
  await page.getByRole('button', { name: /continue to payment/i }).click();
  await page.getByPlaceholder('e.g. Johnathan Doe').fill('Jane Doe');
  await page.getByPlaceholder('0000 0000 0000 0000').fill('4242 4242 4242 4242'); // Omise TEST card
  await page.getByPlaceholder('MM/YY').fill('12/29');
  await page.getByPlaceholder('•••').fill('123');
  await page.getByLabel(/agree to the terms/i).check();
  await page.getByRole('button', { name: /pay .* securely/i }).click();
  await expect(page.getByRole('heading', { name: 'Booking Confirmed!' })).toBeVisible({ timeout: 30_000 });
});
```

<div class="small">Test cards only. Never real card numbers.</div>

<!--
SAY: The journey test proves the whole chain works: UI, booking API, payment, confirmation with a PNR. We keep exactly one or two of these and tag them @smoke so CI can run just those.
Unique email per run: the booking API ties data to the email, a hard-coded one collides with yesterday's run.
Instructor note: Omise tokenization needs internet. If offline, skip the live pay and use the mocked decline path from Module 6.
